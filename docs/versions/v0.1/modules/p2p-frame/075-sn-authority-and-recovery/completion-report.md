# 075-sn-authority-and-recovery Completion Report

## Object and Scope

- Task manifest: task.yaml
- Workflow tier: standard
- Proposal: proposal.md (status approved, final tier standard)
- Change record: docs/changes/075-sn-authority-and-recovery.md
- Delivery scope: `p2p-frame` SN NAT-probe authority identity, rendezvous ambiguous-failure mapping, and ActiveSN eviction scope; no wire/protocol/CLI/dependency change.

## Delivery Summary

- Outcome: a `ReportSn` that the client multiplexes onto a second command stream over the same bearer is no longer discarded — the server accepts probe results and `net_profile` from any UDP command stream on the peer's registered observed address while still ignoring a different observed path and any TCP tunnel; `rendezvous_via_sn` maps SN command QA failures back to `IoError` so `TunnelManager` still runs its local punch/wait remedy after a lost or timed-out response; and a single failed command-stream acquisition no longer deletes the whole ActiveSN, which is now evicted only after two consecutive acquisition failures while send/response failures never evict it.
- Handoff: the authority gate is now "peer + registered observed address", so future SN command-multiplexing work must keep the invariant that all command streams opened on demand share one bearer/observed address; the eviction policy is a bounded approximation until `sfo-cmd-server` exposes a read-only "is a matching stream alive?" query.
