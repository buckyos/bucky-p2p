## Delivery Summary

- Outcome: `reconcile_nat_probe_authority` no longer deletes a peer registration (and no longer clears the published NAT profile) just because the command stream that established it is missing. It now keeps the authority while any accepted command stream of that authenticated peer matches the registered observed path, using the same protocol+address predicate that `is_authoritative_report` uses for report acceptance, so the two checks can no longer disagree; a registration whose observed path has no accepted stream is still recycled with the existing `TunnelMissing` semantics.
- Handoff: authority identity is now "authenticated peer + registered observed path" on both the acceptance and the liveness side; future SN command-multiplexing changes must keep `same_observed_path` as the single rule and must not reintroduce a tunnel-id-only liveness check. Reported separately as F-076-2: a client-side command-stream close is not signalled to the peer, so the server keeps such a stream until its bearer closes.
