## Delivery Summary

- Outcome: `TunnelManager::open_direct_path` no longer abandons in-flight direct candidates by dropping them (quinn reported that to the peer as `ApplicationClose { error_code: 0, reason: b"" }`); losers stay alive until their own attempt finishes and are then closed explicitly, and only the selected candidate is registered/published (with `conn_info_cache` updated for it alone). Tunnel reuse now prefers a candidate that already carried business traffic — most recently used first — and falls back to the historical newest-registration order only among never-used candidates, so a freshly registered loser no longer wins over the candidate that is actually in use.
- Handoff: a human diagnostic run of the local `cyfs-p2p-test all-in-one` scenario exercised the new path (4 × `direct path abandoned candidate close`, and peer-side closes now carry `reason: b"tunnel closed"` with zero `reason: b""` occurrences); that run is diagnostics only and is not used as verification evidence (see `harness/custom-rules/cyfs-p2p-test-stage-ban-rules.md`). Follow-up candidate: make abandoned candidates explicit-close safe when the whole `open_direct_path` future is cancelled (hedged reverse winner, rendezvous deadline/collision cancel), which needs proposal/tier reconfirmation.
